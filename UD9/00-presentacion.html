UD9. Aplicaciones Web híbridas: librerías y repositorios heterogéneos (Composer)

Presentación de la unidad

Qué aprenderás

Esta unidad cierra el módulo con un cambio de enfoque: hasta ahora habéis construido cada pieza desde cero; aquí el objetivo es reutilizar. Una aplicación Web híbrida combina código propio, librerías de terceros e información procedente de repositorios heterogéneos (APIs, datos abiertos, ficheros CSV/JSON, bases de datos propias o ajenas).

La aplicación Laravel de las unidades anteriores es la base de trabajo, y la API REST que construisteis en la UD7 se consume aquí como una fuente más: cerráis el círculo del módulo actuando a la vez como proveedores y consumidores.

Objetivos

  • Valorar las ventajas de reutilizar código e información existente frente a desarrollar desde cero.
  • Gestionar dependencias con Composer: composer.json, versionado semántico y autoload PSR-4.
  • Consumir repositorios de información existentes desde el servidor con Guzzle, incluidas APIs autenticadas.
  • Crear repositorios propios a partir de fuentes externas con un proceso ETL (extraer, transformar, cargar).
  • Incorporar funcionalidades completas mediante librerías de terceros: generación de PDF y códigos QR.
  • Construir un cuadro de mando con indicadores calculados sobre datos reales (analítica e inteligencia de negocios).
  • Probar, depurar y documentar aplicaciones que dependen de fuentes externas.

El proyecto de la unidad

Los ejercicios de proyecto encadenan sobre una misma aplicación: la fuente que consumes alimenta tu repositorio propio, que a su vez es la base del PDF, del QR y del cuadro de mando final. Cada sección deja el punto de partida listo para el siguiente.

Recursos y materiales

  • Docker (obligatorio desde esta unidad — ver Laravel: instalación y estructura)
  • MySQL/MariaDB (vía el servicio db del docker-compose.yml, no instalación aparte)
  • PHP 8.2+, Composer y tu proyecto Laravel 13.x de las unidades anteriores (o uno nuevo).
  • MySQL/MariaDB/PostreSQL/AmazonRDS con la base de datos de prácticas.
  • Visual Studio Code con las extensiones de PHP y Laravel ya instaladas.
  • Navegador con herramientas de desarrollador.
  • Documentación de referencia: php.net y Packagist para localizar librerías de terceros.

Criterios de apto en los ejercicios de proyecto

Se entrega una sola vez, al cerrar EJ11, el estado final de la aplicación. Como los ejercicios de proyecto encadenan sobre la misma aplicación, esa entrega contiene por construcción el buscador de dos fuentes (EJ5), el repositorio propio con su comando de importación (EJ7), el PDF y el QR (EJ9) y el cuadro de mando (EJ11), junto con el README que incluye la justificación de dependencias de EJ3.

La entrega es apta cuando cumple esta lista:

  • La aplicación ejecuta sin errores (una entrega que no ejecuta no puede ser apta).
  • El buscador consulta las dos fuentes con timeout, gestión de errores independiente por fuente y registro en el log.
  • El comando de importación carga datos reales y, reejecutado, no duplica registros.
  • La exportación a PDF y el código QR por registro funcionan sobre los datos del repositorio propio.
  • El cuadro de mando muestra al menos cuatro KPI correctos y una gráfica alimentada desde el controlador.
  • La memoria breve interpreta los indicadores en términos de negocio.
  • El README recoge las dependencias con su justificación y las instrucciones de importación.
  • Los servicios y comandos añadidos llevan PHPDoc.

La copia entre entregas supone no apto para todas las partes implicadas.

ImportanteNormativa · RA-CE

La entrega única está diseñada para que una sola corrección aporte evidencia de todos los criterios de evaluación del RA9: la justificación del README cubre CE9.a y CE9.b; el buscador, CE9.c y CE9.e; la importación, CE9.d; el PDF y el QR, CE9.e y CE9.f; el cuadro de mando y su memoria, CE9.g; y la documentación y las pruebas transversales, CE9.h. La prueba escrita evalúa, además, todos los criterios de forma individual.

La prueba objetiva

El examen combina los contenidos teórico-prácticos sobre un supuesto distinto al trabajado en clase: la preparación debe centrarse entendiendo bien la implementación del proyecto de la uidad.

Todo lo que aparece en las secciones de esta unidad (Composer y semver, consumo de repositorios, ETL, librerías de terceros, analítica y documentación) es contenido de esta prueba.
