Documentación

phpDocumentor

ImportanteNormativa · RA-CE

CE3.g — Se han añadido comentarios al código.

Documenta tus funciones con bloques phpDoc. Los IDEs leen estos bloques y ofrecen autocompletado y validación.

Un comentario normal (// o /* ... */) lo lee solo una persona. Un bloque PHPDoc (/** ... */) es un comentario con una estructura estándar que además pueden leer las herramientas: el editor lo usa para el autocompletado y para avisarte de errores de tipos, y un generador lo convierte en una web de documentación.

NotaConcepto clave

Conviene no confundir dos nombres parecidos:

  • PHPDoc es la sintaxis de los comentarios /** ... */ con etiquetas como @param o @return. No se instala: se escribe.
  • phpDocumentor es la herramienta que lee esos comentarios y genera una web HTML con la documentación del proyecto. Esa sí hay que ponerla en marcha (lo veremos al final de esta sección).

Estructura de un bloque PHPDoc

<?php
/**
 * Valida el formato de un DNI español.
 *
 * @param string $dni Cadena a validar, p. ej. "12345678Z".
 * @return bool true si el formato es correcto.
 */
function validarDNI(string $dni): bool {
    return preg_match('/^[0-9]{8}[A-Z]$/', $dni) === 1;
}

var_dump(validarDNI("12345678Z")); // true
var_dump(validarDNI("1234567z"));  // false
var_dump(validarDNI("123456"));    // false

/**
 * Convierte una temperatura de grados Celsius a Fahrenheit.   ← resumen (una línea)
 *
 * Aplica la fórmula F = C × 9/5 + 32. El resultado se          ← descripción (opcional)
 * redondea al número de decimales indicado.
 *
 * @param float $celsius    Temperatura en grados Celsius.      ← etiquetas
 * @param int   $decimales  Decimales del resultado (por defecto 1).
 * @return float Temperatura en grados Fahrenheit.
 */
function celsiusAFahrenheit(float $celsius, int $decimales = 1): float {
    return round($celsius * 9 / 5 + 32, $decimales);
}

echo celsiusAFahrenheit(25);      // 77
echo celsiusAFahrenheit(36.6, 2); // 97.88
?>

Reglas de forma:

  • Empieza exactamente por /** (dos asteriscos). Con uno solo (/*) es un comentario normal y ninguna herramienta lo reconoce.
  • Va inmediatamente encima del elemento que documenta, sin líneas de código entre medias.
  • La primera frase es el resumen; deja una línea en blanco antes de la descripción y de las etiquetas.

Tipos más precisos que los de PHP

PHPDoc permite describir tipos que el tipado nativo de PHP no puede expresar, sobre todo el contenido de los arrays:

<?php
/**
 * Calcula la media de una lista de temperaturas.
 *
 * @param float[] $lecturas Lista de temperaturas (no vacía).
 * @return float Media aritmética.
 * @throws InvalidArgumentException Si la lista está vacía.
 */
function mediaTemperaturas(array $lecturas): float {
    if ($lecturas === []) {
        throw new InvalidArgumentException("La lista no puede estar vacía");
    }
    return array_sum($lecturas) / count($lecturas);
}

/**
 * Devuelve la ciudad con la temperatura más alta.
 *
 * @param array<string, float> $porCiudad Ciudad => temperatura.
 * @return string|null Nombre de la ciudad, o null si el array está vacío.
 */
function ciudadMasCalurosa(array $porCiudad): ?string {
    if ($porCiudad === []) {
        return null;
    }
    arsort($porCiudad);
    return array_key_first($porCiudad);
}

echo mediaTemperaturas([18.5, 21.0, 19.5]);                       // 19.666666666667
echo ciudadMasCalurosa(["Alicante" => 27.5, "Teruel" => 14.0]);   // Alicante
?>
Notación PHPDoc Significado
float[] Array indexado de float
array<string, float> Array asociativo: claves string, valores float
string\|null o ?string Una cadena o null
int\|false Un entero o false (típico de funciones nativas como array_search)
mixed Cualquier tipo

Escribir PHPDoc en VS Code

Con la extensión PHP Intelephense instalada:

  1. Sitúate en la línea vacía encima de una función ya escrita.
  2. Escribe /** y pulsa Intro: se genera el esqueleto del bloque con un @param por cada parámetro y el @return, con los tipos ya rellenos a partir de la firma.
  3. Completa el resumen y la descripción de cada etiqueta.

A partir de ese momento, al pasar el ratón por encima de cualquier llamada a la función, VS Code muestra su documentación.

AdvertenciaErrores frecuentes

Si el tipo del PHPDoc y el de la firma no coinciden (@param int $precio en una función float $precio), el editor no se queja siempre, pero la documentación generada miente. Cuando cambies la firma de una función, revisa también su bloque PHPDoc.

Generar la documentación con phpDocumentor

phpDocumentor recorre las carpetas del proyecto, lee todos los bloques PHPDoc y genera una web navegable con un índice de ficheros y funciones.

En nuestro entorno el código está en una carpeta de Windows y Docker se ejecuta dentro de Ubuntu (WSL), que ve esa carpeta en la ruta /mnt/c/.... Por eso no instalamos nada en Windows ni en Ubuntu: usamos la imagen Docker oficial phpdoc/phpdoc:3, que ya trae PHP y todo lo necesario, y le “prestamos” la carpeta del proyecto.

Windows                              Ubuntu (WSL)                      Contenedor phpdoc
C:\Users\alumno\dwes\ud3   ──────▶   /mnt/c/Users/alumno/dwes/ud3   ──▶   /data
        (tus .php)                     (misma carpeta, otra ruta)          (lee .php, escribe docs/api)

Paso 1 - Abrir un terminal de Ubuntu en la carpeta del proyecto

Cualquiera de estas dos opciones sirve:

  • Desde VS Code: abre el terminal integrado y elige el perfil Ubuntu (WSL) en el desplegable + ▾.
  • Desde el Explorador de Windows: entra en la carpeta del proyecto, escribe wsl en la barra de direcciones y pulsa Intro.

Comprueba que estás en el sitio correcto y que Docker responde:

pwd
# /mnt/c/Users/alumno/dwes/ud3

docker ps
# CONTAINER ID   IMAGE   ...   (una tabla, aunque esté vacía)

La equivalencia de rutas es directa: C:\Users\alumno\dwes\ud3 → /mnt/c/Users/alumno/dwes/ud3 (la unidad en minúscula y las barras al revés).

Paso 2 - Primera generación

docker run --rm -v "$(pwd)":/data phpdoc/phpdoc:3 run -d . -t docs/api
Parte del comando Qué hace
docker run --rm Crea un contenedor y lo elimina al terminar
-v "$(pwd)":/data Monta la carpeta actual dentro del contenedor en /data
phpdoc/phpdoc:3 Imagen oficial de phpDocumentor (versión 3)
run -d . Analiza la carpeta actual (-d = directorio de origen)
-t docs/api Escribe la web generada en docs/api (-t = destino)

La primera vez tarda un poco porque descarga la imagen. Las siguientes ejecuciones duran pocos segundos:

Applying transformations (can take a while)

All done in 2 seconds!

Al terminar tendrás dos carpetas nuevas en el proyecto: docs/api (la documentación) y .phpdoc (caché interna, que acelera las siguientes ejecuciones).

Paso 3 - Ver el resultado

La documentación son ficheros HTML estáticos, así que basta con abrir docs/api/index.html:

  • Desde Windows: doble clic sobre docs\api\index.html en el Explorador.
  • Desde el terminal de Ubuntu: explorer.exe . abre la carpeta actual en el Explorador de Windows.
  • Desde tu servidor Docker: si docs/ queda dentro de la raíz web de tu proyecto, también la verás en http://localhost:<puerto>/docs/api/.

En la web generada, el apartado Functions del espacio de nombres global lista todas las funciones con su resumen, parámetros y valor de retorno.

Paso 4 - Fichero de configuración (recomendado)

Para no recordar las opciones, crea en la raíz del proyecto un fichero llamado exactamente phpdoc.dist.xml. phpDocumentor lo busca y lo aplica de forma automática:

<?xml version="1.0" encoding="UTF-8" ?>
<phpdocumentor configVersion="3"
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xmlns="https://www.phpdoc.org"
    xsi:noNamespaceSchemaLocation="https://raw.githubusercontent.com/phpDocumentor/phpDocumentor/master/data/xsd/phpdoc.xsd">
    <title>UD3 · Estructuras de control</title>
    <paths>
        <output>docs/api</output>
        <cache>.phpdoc/cache</cache>
    </paths>
    <version number="latest">
        <api>
            <source dsn=".">
                <path>.</path>
            </source>
            <ignore hidden="true" symlinks="true">
                <path>docs/**/*</path>
                <path>vendor/**/*</path>
            </ignore>
            <default-package-name>UD3</default-package-name>
        </api>
    </version>
</phpdocumentor>

Con el fichero en su sitio, el comando se reduce a:

docker run --rm -v "$(pwd)":/data phpdoc/phpdoc:3

Paso 5 - Atajo phpdoc (opcional)

Para escribir solo phpdoc, añade esta función al final de ~/.bashrc en Ubuntu:

nano ~/.bashrc
# phpDocumentor vía Docker: monta la carpeta actual y ejecuta la herramienta
phpdoc() {
    docker run --rm -v "$PWD":/data phpdoc/phpdoc:3 "$@"
}

Guarda (Ctrl+O, Intro, Ctrl+X), recarga la configuración y pruébalo:

source ~/.bashrc
cd /mnt/c/Users/alumno/dwes/ud3
phpdoc
# All done in 1 seconds!

Paso 6 - No subir la documentación generada al repositorio

La documentación se regenera en segundos, así que no tiene sentido versionarla. Añade estas líneas a .gitignore:

docs/api/
.phpdoc/
AdvertenciaErrores frecuentes
  • docker: command not found: estás en PowerShell o CMD. Docker está instalado dentro de Ubuntu (WSL), así que el comando debe lanzarse desde un terminal de Ubuntu.
  • La documentación sale vacía o con ficheros de otra carpeta: el comando se ejecutó desde una carpeta distinta a la raíz del proyecto. Comprueba con pwd antes de lanzarlo.
  • Usar un alias con comillas dobles (alias phpdoc="docker run -v '$(pwd)':/data ..."): $(pwd) se evalúa una sola vez, al cargar ~/.bashrc, y el alias documenta siempre la misma carpeta. Usa la función del paso 5.
  • “No errors have been found” no significa que todo esté documentado. El informe Errors de phpDocumentor no avisa de las funciones que no tienen bloque PHPDoc. Revisa el apartado Functions: una función sin resumen ni descripciones de parámetros es una función sin documentar.

EJ9 · Ejercicios extras de funciones

En el proyecto de ejemplo creado en la actividad anterior, crea un fichero PHP llamado funciones.php y resuelve los siguientes ejercicios:

1. Generador de consultas INSERT INTO (Paso por valor)

Queremos crear una función llamada insert que nos genere una sentencia INSERT INTO en SQL de forma dinámica. Para ello, la función recibirá dos parámetros: el nombre de la tabla y un array asociativo que contendrá los nombres de los campos (claves) y sus respectivos valores.

La sentencia resultante devuelta por la función debe tener la siguiente estructura: "INSERT INTO nombre_tabla (campos, separados, por, comas) VALUES (:campos, :separados, :por, :comas)"

  • Nota: De momento no operaremos con los valores del array, solo con sus claves para preparar los named placeholders de PDO.

  • Ayuda: Utiliza las funciones nativas sprintf, implode y array_keys.

2. Generador de consultas SQL (Paso por referencia)

Repite el ejercicio anterior aplicando una lógica diferente basada en plantillas y paso por referencia:

  • La función recibirá la cadena base por referencia inicializada de la siguiente forma: $sql = "INSERT INTO tabla (campos) VALUES (valores)";

  • Dentro de la función, deberás buscar y sustituir los textos comodín:

    • El texto tabla por el nombre real de la tabla.
    • El texto campos por los nombres de los campos del array separados por comas.
    • El texto valores por los nombres de los campos separados por comas con el carácter : delante.

3. Calculadora flexible mediante Funciones Anónimas (Callbacks)

Queremos crear una función genérica que calcule y muestre por pantalla el resultado de una operación matemática entre dos operandos.

La salida impresa debe seguir estrictamente este formato:
[Primer operando] [Símbolo] [Segundo operando] = [Resultado]
(Por ejemplo: 5 + 3 = 8)

Para lograr la máxima flexibilidad, la función debe recibir cuatro parámetros:

  1. El primer operando numérico.
  2. El segundo operando numérico.
  3. El símbolo de la operación en formato string (ej: "+", "-", "*").
  4. Una función anónima (closure / callback) que se encargará de realizar internamente la operación aritmética correspondiente y devolver el resultado.
