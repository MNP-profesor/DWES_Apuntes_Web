Formularios HTML

ImportanteNormativa · RA-CE

CE3.e — Se han utilizado formularios web para interactuar con el usuario del navegador web.

El elemento <form>

Un formulario agrupa controles de entrada y define a dónde y cómo se envían los datos:

<form action="procesar.php" method="post">
    <label for="nombre">Nombre:</label>
    <input type="text" id="nombre" name="nombre" required>

    <label for="curso">Curso:</label>
    <select id="curso" name="curso">
        <option value="daw">2º DAW</option>
        <option value="dam">2º DAM</option>
    </select>

    <button type="submit">Enviar</button>
</form>
NotaConcepto clave

El atributo name (no id) de cada control es la clave con la que PHP recibirá el dato. Si un control no tiene name, su valor no se envía.

Controles habituales

<!-- Texto de una línea -->
<input type="text"     name="usuario"  placeholder="Tu nombre">
<input type="email"    name="correo"   required>
<input type="password" name="clave">
<input type="number"   name="edad"     min="0" max="120">
<input type="date"     name="fecha">
<input type="hidden"   name="token"    value="abc123">

<!-- Texto multilínea -->
<textarea name="comentario" rows="4" cols="40"></textarea>

<!-- Lista desplegable -->
<select name="pais">
    <option value="es">España</option>
    <option value="fr">Francia</option>
    <option value="pt" selected>Portugal</option>
</select>

<!-- Botones de opción (radio): solo uno del grupo -->
<input type="radio" name="modalidad" value="presencial" id="r1">
<label for="r1">Presencial</label>
<input type="radio" name="modalidad" value="online" id="r2" checked>
<label for="r2">Online</label>

<!-- Casilla de verificación -->
<input type="checkbox" name="condiciones" value="1" id="ck1">
<label for="ck1">Acepto las condiciones</label>

<!-- Subida de archivos -->
<input type="file" name="avatar">

<!-- Envío -->
<button type="submit">Enviar</button>
<button type="reset">Limpiar</button>
Importante¡Obligatorio para subir archivos!

Para que el navegador pueda empaquetar y enviar un archivo binario (como una imagen o un PDF), el elemento <form> debe incluir obligatoriamente el atributo enctype="multipart/form-data" y utilizar el método POST. Si se te olvida, PHP no recibirá el archivo.

<form action="subir.php" method="post" enctype="multipart/form-data">
    <input type="file" name="documento">
    <button type="submit">Subir archivo</button>
</form>

GET frente a POST

GET POST
Donde están los datos URL (?campo=valor&...) Cuerpo de la petición
Límite de longitud de la URL ~2–8 KB según navegador Sin límite
Visible en historial Sí (porque la petición entera está en la URL) No
Cacheable Sí (porque la petición entera está en la URL) No
Uso Búsquedas, filtros, paginación Registro, login, envío de archivos 
<!-- GET: adecuado para un buscador — la URL se puede compartir -->
<form action="buscar.php" method="get">
    <input type="text" name="q" placeholder="Buscar...">
    <button type="submit">Buscar</button>
</form>
<!-- URL resultante: buscar.php?q=php+arrays -->
<!-- POST: adecuado para un formulario de login -->
<form action="login.php" method="post">
    <input type="text"     name="usuario">
    <input type="password" name="clave">
    <button type="submit">Entrar</button>
</form>
<!-- Los datos van en el cuerpo, no en la URL -->
Advertencia¡Cuidado!

Nunca uses GET para enviar contraseñas o datos personales. La URL queda en el historial del navegador, en los registros del servidor y en la cabecera Referer al hacer clic en enlaces externos.

Imagina un login mal hecho por GET:

http://mitienda.com/login.php?usuario=ana&password=secreto123

Si desde esa misma página, después de loguearte, hay un enlace o un botón que lleva a un sitio externo (un banner de publicidad, un enlace a “Síguenos en redes”, un widget de terceros embebido).

<a href="https://anuncios-externos.com/promo">Ver oferta especial</a>

Cuando el usuario hace clic ahí, el navegador le dice automáticamente a anuncios-externos.com, en la cabecera Referer de esa nueva petición, desde qué URL vino, es decir, le envía literalmente:

Referer: http://mitienda.com/login.php?usuario=ana&password=secreto123

Por tanto, el propietario de anuncios-externos.com (o cualquiera con acceso a sus logs) acaba de recibir tu usuario y tu contraseña.

Un formulario de contacto con soporte técnico, con varios tipos de control:

<!DOCTYPE html>
<html lang="es">
<head><meta charset="UTF-8"><title>Contactar con soporte</title></head>
<body>
<form action="enviar_contacto.php" method="post">

    <label for="email">Tu correo electrónico:</label>
    <input type="email" id="email" name="email" required>
    <br>

    <label for="departamento">Departamento:</label>
    <select id="departamento" name="departamento">
        <option value="">-- Elige --</option>
        <option value="tecnico">Soporte técnico</option>
        <option value="facturacion">Facturación</option>
        <option value="comercial">Comercial</option>
    </select>
    <br>

    <fieldset>
        <legend>Prioridad</legend>
        <input type="radio" id="baja" name="prioridad" value="baja" checked>
        <label for="baja">Baja</label>
        <input type="radio" id="alta" name="prioridad" value="alta">
        <label for="alta">Alta</label>
    </fieldset>

    <label for="mensaje">Mensaje:</label>
    <textarea id="mensaje" name="mensaje" rows="4" required></textarea>
    <br>

    <input type="checkbox" id="ck" name="suscribir" value="1">
    <label for="ck">Quiero recibir novedades por email</label>
    <br><br>

    <button type="submit">Enviar consulta</button>
</form>
</body>
</html>

EJ10 · Formulario de inscripción

El centro va a abrir un formulario web para que el alumnado se inscriba a los ciclos de FP que oferta, sustituyendo el papel que se rellenaba hasta ahora en secretaría. Necesitas construir la página del formulario.

Crea el fichero inscripcion.html con un formulario que cumpla estos requisitos:

  • Campos: nombre completo (texto, obligatorio), email (obligatorio), curso (select con al menos 3 opciones), modalidad (radio con “Presencial” y “Semipresencial”), checkbox de aceptación de condiciones (obligatorio).
  • Utiliza el método que consideres correcto: GET o POST.
  • Añade un comentario HTML al inicio explicando por qué se usas el método.
  • Acción: procesar_inscripcion.php.
  • Cada control debe tener su <label> asociado con for/id.
  • Botón de envío con texto “Enviar inscripción”.

En este ejercicio no hace falta que procesar_inscripcion.php exista todavía porque se crea en EJ11.
