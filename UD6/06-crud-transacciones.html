CRUD completo: transacciones e integridad

Hasta este apartado de la unidad tan solo hemos consultado información. Modificar datos (INSERT, UPDATE, DELETE) usa el mismo patrón de sentencia preparada, y añade un requisito: la integridad.

Insertar

<?php
$sql = 'INSERT INTO socios (nombre, email, alta)
        VALUES (:nombre, :email, CURDATE())';
$st = $pdo->prepare($sql);
$st->execute([
    ':nombre' => $_POST['nombre'],
    ':email'  => $_POST['email'] ?: null,
]);
$nuevoId = $pdo->lastInsertId();
echo "Alta del socio #$nuevoId";

Transacciones: todo o nada

Algunas operaciones son en realidad dos o más pasos que deben ocurrir juntos: si uno falla, ninguno debe quedar aplicado. El ejemplo clásico es una transferencia bancaria entre dos cuentas — deliberadamente fuera del esquema de la biblioteca, para que veas el patrón aislado antes de aplicarlo tú a socios/libros/prestamos:

<?php
// Ejemplo conceptual — no forma parte del esquema de la biblioteca
$cuentaOrigen = 1;
$cuentaDestino = 2;
$importe = 50;

try {
    $pdo->beginTransaction();

    // 1) Descontar del origen, solo si hay saldo suficiente
    $salida = $pdo->prepare('UPDATE cuentas SET saldo = saldo - :importe
                              WHERE id = :id AND saldo >= :importe');
    $salida->execute([':importe' => $importe, ':id' => $cuentaOrigen]);

    if ($salida->rowCount() === 0) {
        throw new RuntimeException('Saldo insuficiente.');
    }

    // 2) Abonar en el destino
    $pdo->prepare('UPDATE cuentas SET saldo = saldo + :importe WHERE id = :id')
        ->execute([':importe' => $importe, ':id' => $cuentaDestino]);

    $pdo->commit();          // ambas o ninguna
    echo 'Transferencia realizada.';
} catch (Throwable $e) {
    $pdo->rollBack();        // deshace todo si algo falla
    error_log($e->getMessage());
    echo 'No se pudo completar la transferencia.';
}

Salida esperada (la cuenta 1 tiene saldo suficiente):

Transferencia realizada.

Si la cuenta origen no tuviera los 50€ (saldo < :importe), el primer UPDATE no afectaría a ninguna fila, se lanzaría la excepción y el rollBack dejaría ambas cuentas exactamente igual que antes: ni descuento ni abono.

Salida esperada:

No se pudo completar la transferencia.

El patrón es siempre el mismo, tengas cuentas bancarias, préstamos de libros o cualquier otra operación de varios pasos: beginTransaction() → comprobar cada paso (rowCount() === 0 indica que la condición de un UPDATE no se cumplió) → commit() si todo fue bien, rollBack() en el catch si algo falló.

NotaConcepto clave

El RA exige “seguridad e integridad”:

  • Seguridad → sentencias preparadas (frente a inyección).
  • Integridad → transacciones (commit / rollBack) y restricciones del SGBD (claves foráneas, NOT NULL, UNIQUE), que evitan estados intermedios inconsistentes (un préstamo sin copia descontada, o al revés).

Actividades

EJ4 · CRUD con validación y transacciones

Implementa la gestión de socios, libros y préstamos de la biblioteca. Parte de la clase Conexion de EJ1 y del patrón de transacción visto en este bloque.

La implementación constará de cuatro operaciones:

  1. Alta de socio (alta_socio.php):
  • Formulario con validación en servidor: nombre obligatorio (máx. 80 caracteres) y email con formato válido y único en la tabla.
  • Inserción con sentencia preparada y recuperación del id generado.
  • Ante datos inválidos, reaparece el formulario con los valores introducidos y los errores. Decide tú cómo detectas el email duplicado (por consulta previa o capturando la violación de la restricción UNIQUE).
  1. Prestar un libro (prestar.php):
  • Recibe un socio y un libro y registra el préstamo en una transacción: descuenta una copia libre y crea el registro en prestamos, todo o nada.
  • Si el libro no tiene copias libres, no debe cambiar nada y hay que informar del motivo.
  1. Devolver libro / Baja de socio (devolver.php, baja_socio.php):
  • La devolución marca fecha_devolucion y repone una copia libre (de nuevo, en una sola transacción).
  • La baja de un socio debe respetar la integridad: no se permite borrar un socio con préstamos activos (sin devolver).
  1. Eliminar libro (baja_libro.php):
  • Elimina un libro del catálogo con sentencia preparada.
  • Misma regla de integridad que la baja de socio: no se permite eliminar un libro con préstamos activos asociados (compruébalo antes del DELETE, o captura la violación de la clave foránea).

Para evaluar el correcto funcionamiento del ejercicio debes realizar, al menos, las siguientes pruebas:

Préstamo de libro sin copias Prestar “Fundación” (0 libres) rollBack: nada cambia

NotaInformación

El ejercicio estará correcto si el préstamo y la devolución son transaccionales y verificables (una copia mal contada es un fallo), la validación del alta ocurre en servidor, y tanto la baja de socio como la de libro respetan la integridad referencial. Demostrar que un préstamo fallido no deja la base de datos a medias.

Eloquent por debajo

En la UD5 escribías Libro::find(1) o $libro->save() sin ver el SQL. Ahora entiendes qué hace Eloquent por debajo: cada método genera una sentencia preparada PDO como las que has escrito a mano.

NotaConcepto clave

El ORM aporta comodidad sobre lo que acabas de aprender a hacer manualmente.

En Eloquent (UD5) Por debajo (PDO, esta unidad)
Libro::find(1) SELECT * FROM libros WHERE id = :id
Libro::all() SELECT * FROM libros
$l->save() (nuevo) INSERT INTO libros (...) VALUES (...)
$l->save() (existente) UPDATE libros SET ... WHERE id = :id
$l->delete() DELETE FROM libros WHERE id = :id
