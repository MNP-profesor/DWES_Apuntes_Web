Modos de recuperación y conjuntos de datos

Modos de recuperación

El modo de recuperación (fetch mode) decide qué estructura recibes por cada fila:

Modo Qué devuelve Cuándo usarlo
FETCH_ASSOC Array asociativo columna => valor Caso general, el que suele ponerse
FETCH_NUM Array con índices numéricos Consultas simples / rendimiento
FETCH_OBJ Objeto anónimo con propiedades Acceso con ->propiedad sin clase propia
FETCH_CLASS Instancia de una clase tuya Cuando ya tienes un modelo
NotaInformación

Recuerda que en la clase Conexion que ya has implementado, utilizas el atributo ATTR_DEFAULT_FETCH_MODE => FETCH_ASSOC. Es el que se pone normalmente por defecto.

En el siguiente ejemplo se obtiene el mismo dato con dos modos distintos:

<?php
// FETCH_ASSOC
$fila = $pdo->query('SELECT titulo FROM libros LIMIT 1')->fetch(PDO::FETCH_ASSOC);
echo $fila['titulo'] . "<br>";   // acceso por clave

// FETCH_OBJ
$fila = $pdo->query('SELECT titulo FROM libros LIMIT 1')->fetch(PDO::FETCH_OBJ);
echo $fila->titulo . "<br>";     // acceso por propiedad

Salida esperada:

El nombre del viento
El nombre del viento

FETCH_CLASS crea y rellena objetos de una clase tuya, asignando cada columna a la propiedad del mismo nombre:

<?php
class Libro {
    public int $id;
    public string $titulo;
    public string $autor;

    public function etiqueta(): string {
        return $this->titulo . ' - ' . $this->autor;
    }
}

$st = $pdo->query('SELECT id, titulo, autor FROM libros ORDER BY titulo LIMIT 3');
$libros = $st->fetchAll(PDO::FETCH_CLASS, Libro::class);

foreach ($libros as $l) {          // $l es un objeto Libro
    echo $l->etiqueta() . "<br>";
}

Salida esperada (los tres primeros por orden alfabético; el catálogo completo tiene más):

1984 — George Orwell
Crónica de una muerte anunciada — Gabriel García Márquez
El código Da Vinci — Dan Brown
TipAnalogía Java

En Java construías el objeto y después rellenabas sus campos recorriendo el ResultSet. PDO con FETCH_CLASS hace lo contrario, y esto sorprende: asigna las propiedades ANTES de ejecutar el constructor. Si tu constructor pone valores por defecto, los pisará. Para que el constructor corra primero, combina las banderas: fetchAll(PDO::FETCH_CLASS | PDO::FETCH_PROPS_LATE, Libro::class).

El conjunto de datos: qué hacer con él una vez recuperado

fetchAll() no te da una fila: te da el conjunto completo de resultados, un array con un elemento por fila. Una vez está en PHP, ya no hace falta volver a la base de datos para filtrarlo, ordenarlo o resumirlo — son operaciones sobre un array normal, con las funciones de orden superior que ya conoces de UD3 (array_filter, array_map, array_reduce), ahora aplicadas sobre un array de objetos en vez de arrays asociativos.

Sobre el mismo $libros del ejemplo anterior:

<?php
// Solo los libros con copias disponibles
$disponibles = array_filter($libros, fn (Libro $l) => $l->copias_libres > 0);

// Solo los títulos, como array de strings
$titulos = array_map(fn (Libro $l) => $l->titulo, $libros);

// Total de copias libres en todo el conjunto
$totalLibres = array_reduce($libros, fn ($acum, Libro $l) => $acum + $l->copias_libres, 0);

echo count($disponibles) . ' de ' . count($libros) . " libros disponibles\n";
echo "Copias libres en total: $totalLibres\n";

Salida esperada (sobre el catálogo completo de 17 libros, no solo los 3 del LIMIT anterior):

14 de 17 libros disponibles
Copias libres en total: 32
NotaConcepto clave

La diferencia con los modos de fetch de arriba: el modo decide qué forma tiene cada fila al llegar desde la base de datos; esto es sobre qué haces en PHP con el conjunto entero una vez ya lo tienes. Son dos cosas distintas aunque aparezcan en la misma sección.

  1. Listado (catalogo.php: listado con búsqueda, paginación y objetos):
  • Muestra los libros en una tabla con su título, autor y número de copias libres.
  • Incluye un buscador por título con LIKE parametrizado que conserve el término tras enviar.
  • Pagina los resultados de 5 en 5 con LIMIT/OFFSET. Inserta más libros para poder probar.
  • Recupera los libros con FETCH_CLASS sobre tu clase Libro, y en la tabla usa un método de esa clase (por ejemplo, uno que indique si el libro está disponible).
  • Sobre el array de objetos ya recuperado (el de la página actual, sin otra consulta SQL), calcula con array_filter cuántos de los libros mostrados están disponibles, y muéstralo como un contador (p. ej. “3 de 5 disponibles”).

Para los siguientes casos, la implementación debe dar los resultados indicados:

Caso Entrada Resultado esperado
id existente ?id=3 Ficha de “1984”
id inexistente ?id=9999 “Libro no encontrado.” (404)
id no numérico ?id=abc Tratado como 0 → “Libro no encontrado.”
id malicioso ?id=0 OR 1=1 “Libro no encontrado.”
XSS en buscador q= <script>alert(1)</script> Se muestra como texto, no se ejecuta
NotaInformación

El ejericio estará correcto si el catálogo usa objetos Libro (no arrays), el contador de disponibles usa array_filter sobre el array ya recuperado (no una segunda consulta SQL), toda consulta con datos externos va parametrizada, la salida está escapada y la tabla de pruebas cubre los cinco casos, incluido el de XSS.
