Clases estáticas, clonado, abstractas e interfaces

Clases estáticas

Una propiedad o método static pertenece a la clase, no a cada objeto: todos los objetos comparten el mismo valor. Se accede con self:: desde dentro y NombreClase:: desde fuera. const declara una constante de clase, siempre estática por naturaleza.

AdvertenciaErrores frecuentes

No confundas esto con static $var dentro de una función (sección 1), que es una variable local que recuerda su valor entre llamadas. Aquí static se aplica a una propiedad o método de una clase, y su valor es compartido por todos los objetos de esa clase.

class Producto {
    const IVA = 0.23;
    private static int $numProductos = 0;

    public function __construct() {
        self::$numProductos++;
    }

    public static function totalCreados(): int {
        return self::$numProductos;
    }
}

new Producto();
new Producto();
new Producto();
echo Producto::totalCreados(); // 3
echo Producto::IVA;            // 0.23

Otro ejemplo, un identificador autoincremental sin necesidad de base de datos:

class Pedido {
    private static int $siguienteId = 1;
    public int $id;

    public function __construct() {
        $this->id = self::$siguienteId;
        self::$siguienteId++;
    }
}

$p1 = new Pedido();
$p2 = new Pedido();
echo $p1->id; // 1
echo $p2->id; // 2

Asignación vs clonado

Al asignar un objeto a otra variable ($b = $a;), ambas variables apuntan al mismo objeto: modificar una modifica la otra. clone crea una copia independiente.

class Carrito {
    public array $items = [];
}

$a = new Carrito();
$a->items[] = 'Teclado';

$asignado = $a;        // misma referencia que $a
$clonado  = clone $a;  // copia independiente

$a->items[] = 'Ratón';

print_r($asignado->items); // ['Teclado', 'Ratón']  — cambió porque es el MISMO objeto
print_r($clonado->items);  // ['Teclado']            — no cambió, es una copia aparte
TipAnalogía Java

Este comportamiento es idéntico al de Java: las variables de tipo objeto guardan una referencia, no el objeto en sí, tanto en PHP como en Java. Lo que sorprende viniendo de tipos primitivos (int, string en PHP) es que esos sí se copian por valor al asignarlos — con objetos, no.

Clases abstractas

Una clase abstract no se puede instanciar directamente; sirve como plantilla para sus subclases. Puede mezclar métodos ya implementados con métodos abstract que obliga a implementar a cada subclase.

abstract class Figura {
    abstract public function area(): float;

    public function describir(): string {
        return 'Área: ' . round($this->area(), 2);
    }
}

class Circulo extends Figura {
    public function __construct(private float $radio) {}

    public function area(): float {
        return pi() * $this->radio ** 2;
    }
}

// new Figura(); // Error fatal: no se puede instanciar una clase abstracta

$c = new Circulo(3);
echo $c->describir(); // Área: 28.27

Interfaces

Una interface define qué métodos debe tener una clase, sin implementarlos. Una clase la adopta con implements y se compromete a implementar todos sus métodos. A diferencia de la herencia (una sola clase padre), una clase puede implementar varias interfaces a la vez.

interface Sonido {
    public function hacerSonido(): string;
}

class Perro implements Sonido {
    public function hacerSonido(): string {
        return 'Guau Guau';
    }
}

class Gato implements Sonido {
    public function hacerSonido(): string {
        return 'Miau Miau';
    }
}

function reproducir(Sonido $s): string {
    return $s->hacerSonido();
}

echo reproducir(new Perro()); // Guau Guau
echo reproducir(new Gato());  // Miau Miau
NotaConcepto clave

Clase abstracta: comparten código y estructura (herencia simple). Interfaz: solo comparten “contrato” (una clase puede implementar varias). En la práctica, muchas clases combinan ambas: heredan de una abstracta y además implementan una o más interfaces.

Métodos útiles de reflexión

Son métodos con la capacidad de examinarse o modificarse a sí mismo (el propio programa) en tiempo de ejecución, es decir, inspeccionar sus propias clases, métodos y propiedades, sin conocerlos de antemano en el código:

class Producto {
    public string $nombre = 'Teclado';
    public function mostrarResumen(): string {
        return $this->nombre;
    }
}

$p = new Producto();

var_dump($p instanceof Producto);           // true
echo get_class($p);                         // "Producto"
var_dump(class_exists('Producto'));         // true
var_dump(method_exists($p, 'mostrarResumen')); // true
var_dump(property_exists($p, 'nombre'));    // true

print_r(get_class_methods('Producto')); // ['mostrarResumen']
print_r(get_object_vars($p));           // ['nombre' => 'Teclado']

if (method_exists($p, 'mostrarResumen')) {
    echo $p->mostrarResumen(); // Teclado
}

Actividades

EJ4 · Empresa: empleados con clase abstracta e interfaz

Modela un sistema de empleados:

Crea una clase abstracta Empleado:

  • nombre (string)
  • salarioBase (float)
  • calcularSalario(): float — método abstracto.
  • mostrarInformacion(): void — muestra nombre y salario (llamando internamente a calcularSalario()).

Crea también una interfaz Bonificable con un único método: porcentajeBono(): float.

Crea tres subclases de Empleado que además implementen Bonificable, sobrescribiendo calcularSalario() para aplicar el bono que devuelve porcentajeBono():

  • JefeEquipo — porcentajeBono() devuelve 0.20 (20% adicional sobre el salario base).
  • Programador — porcentajeBono() devuelve 0.10 (10% adicional).
  • Administrativo — porcentajeBono() devuelve 0.0 (sin bono).

Crea una clase EmpresaPrincipal para probarlo:

  • Crea una lista con empleados de los tres tipos.
  • Recorre la lista e imprime el salario de cada uno usando polimorfismo (una única llamada a calcularSalario() sobre la variable de tipo Empleado, sin comprobar de qué subclase es cada uno con if/instanceof).

Pista: piensa por qué calcularSalario() puede apoyarse en porcentajeBono() de forma genérica en las tres subclases, en vez de repetir la fórmula salarioBase * (1 + porcentaje) tres veces con el número ya puesto a mano.

EJ5 · Concesionario con contador estático y clonado

Amplía las clases Vehiculo/Concesionario de EJ3:

  1. Convierte totalVehiculosCreados en una propiedad static, con un método estático Vehiculo::totalCreados(): int que lo consulte sin necesitar ninguna instancia.

  2. El array de vehículos se copia solo al clonar un Concesionario (PHP copia arrays automáticamente) — pero los objetos Vehiculo que contiene no: siguen siendo el mismo objeto en el original y en el clon. Implementa el método mágico __clone() en Concesionario para que, al clonar, cada Vehiculo de la lista se clone también de forma independiente.

  3. Antes de probar el clonado del concesionario completo, demuestra con un ejemplo más sencillo la diferencia entre asignar ($b = $a) y clonar ($b = clone $a) un único Vehiculo:

    • Con $b = $a: modifica la velocidad de $b y comprueba que $a también cambia (son el mismo objeto, dos nombres de variable distintos).
    • Con $b = clone $a: modifica la velocidad de $b y comprueba que $a no cambia (son objetos independientes).
    • Usa instanceof y get_class() para confirmar que, en ambos casos, $a y $b siguen siendo de la misma clase Vehiculo — lo que cambia es si son el mismo objeto o dos distintos, no su tipo.

Demuestra después, con la traza siguiente, que el mismo problema (y su solución con __clone()) se repite un nivel más arriba, en la lista completa de vehículos de un concesionario:

  • Crea un concesionario con 2 vehículos (A y B).
  • Clónalo: $copia = clone $original;
  • Acelera el vehículo A a través del concesionario clonado.
  • Comprueba la velocidad de A en el concesionario original.

Sin __clone() personalizado: el original también muestra a A acelerado (es el mismo objeto compartido entre las dos listas) — el clonado no es real, solo lo parece.

Con __clone() personalizado (recorriendo el array y clonando cada Vehiculo dentro): el original mantiene a A a velocidad 0 — las dos listas contienen ahora vehículos independientes.
